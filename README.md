# cppgoqt-win

Go bindings for Qt 6.11.1 (QtCore, QtGui, QtWidgets) on Windows, generated by
[cppgo](https://github.com/5k3105/cppgo) with its cgo-free (purego) backend and the Windows
(LLP64) data model. An app using them builds with `CGO_ENABLED=0 GOOS=windows` into one `.exe`
that carries Qt inside it.

## How it fits together

| Stage | Made by | Output |
|---|---|---|
| 1. Bindings | cppgo, from the Windows Qt headers (`regenerate.sh`) | `qt/*.go` (the Go API) and `qt/cshim/*.cpp` (the C++ shims) |
| 2. Shim DLL | the shims compiled with mingw-w64 and linked against a static Qt (`build-dll.sh`) | `qt/shim_qt.dll` |
| 3. App | `go build` of the app, which embeds `qt/shim_qt.dll` | one `.exe` |

At run time the exe writes the DLL to `%LOCALAPPDATA%\cppgoqt\shim_qt-<hash>.dll` once and loads
it (`qt/aaa_bootstrap_windows.go`). The Go side calls the shims' C functions; the shims call Qt.

The generated bindings (stage 1) are committed. `qt/shim_qt.dll` is not: build it once with
stage 2.

## Prerequisites

- Linux x86-64 with Go 1.26 or later.
- mingw-w64 (`x86_64-w64-mingw32-g++`, `-gcc`, `-windres`).
- A static Qt 6.11.1 for mingw: `qt-static/build-qt-static.sh` builds one from the qtbase source.
- To regenerate the bindings only: clang/LLVM with dev headers and a cppgo checkout.

## Build

```sh
# 1. once: a static Qt 6.11.1 for mingw (needs cmake, ninja and a host Qt 6.11.1 for moc/rcc)
QTBASE_SRC=~/src/qtbase-everywhere-src-6.11.1 QT_STATIC=~/qt-6.11.1-mingw-static ./qt-static/build-qt-static.sh

# 2. the shim DLL, from the committed shims
QT_STATIC=~/qt-6.11.1-mingw-static ./build-dll.sh
```

`build-dll.sh` writes `qt/shim_qt.dll`. Its only dependencies are Windows system DLLs.

## Use from an app

Clone this repository beside the app's and point the app's `go.mod` at it:

```
require cppgoqt v0.0.0-00010101000000-000000000000
replace cppgoqt => ../cppgoqt-win
```

```go
import qt "cppgoqt/qt"
```

```sh
CGO_ENABLED=0 GOOS=windows GOARCH=amd64 go build -ldflags "-s -w -H=windowsgui" .
```

## Regenerate the bindings

After a cppgo or Qt version change:

```sh
CPPGO=~/src/cppgo QT_STATIC=~/qt-6.11.1-mingw-static ./regenerate.sh
QT_STATIC=~/qt-6.11.1-mingw-static ./build-dll.sh
```

`regenerate.sh` runs cppgo's frontend on the Windows Qt headers, generates `qt/`, and puts back
the two files cppgo does not generate (`extra/`): the DLL's embed and self-extract
(`aaa_bootstrap_windows.go`) and the static Qt plugin imports (`windows_plugins.cpp`). The shims
include Qt headers relative to the Qt `include` folder, so they build against any static Qt
install.

## Layout

| Path | |
|---|---|
| `qt/` | the generated bindings: Go files, C ABI headers, `cshim/` C++ shims |
| `extra/` | the two hand-written files `regenerate.sh` copies into `qt/` |
| `build-dll.sh` | stage 2: shims + static Qt → `qt/shim_qt.dll` |
| `regenerate.sh` | stage 1: cppgo → `qt/` |
| `qt-static/` | the static Qt build: a mingw toolchain file and its build script |
